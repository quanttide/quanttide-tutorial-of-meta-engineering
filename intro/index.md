# 概念入口

元工程把一段需求变成能跑的代码，走四个阶段：需求、意图、规格、实现。需求把话说明白，意图把话说严谨，规格把严谨的话变成机器能查的表达，实现把表达落进具体的编程语言。四者次序固定，前一阶段的产物是后一阶段的输入；验收不过就退回上一阶段，回退走原路，不许跨阶段追认。

四个阶段各管一件事。需求摊开名词与规矩，说清每个名词的边界、每条规矩何时成立、何时不成立，产物是人话，验收靠人审。意图把需求放回本体坐标，写成集合、关系、逻辑式、状态空间与前置、后置、不变量，交机器验三件事：规矩之间矛盾吗，不变量证得出吗，前置条件够用吗。规格把验过的意图落成与编程语言无关的计算机表达——数据模型、状态表、接口契约，一份规格供多种语言共用，也由它裁定实现有没有削弱意图。实现对着规格落具体语言，规矩可以被类型、约束、测试或证明工具整体接走，两边不必逐条对应。

四个阶段合成一句：一句含糊的需求，经过人审、机器验证、机器检查与细化义务四道关，走到一组在任何语言里都算得出完成与否的东西。数学推理是工具，不是教条——阶段的存在是为了让每一步都可检查，而不是为了多写几层文档。
