# 看清这套方法的数学形状

## 业务需求

前面几篇一路做下来，有几条规则是以纪律的形式留在纸上的：组合之后为什么不用重证？公平调度为什么不能白嫖？「不越界就自动继承」为什么不是一句约定，而是一件能说清的事？

在工程说法里，这几条只能当经验背下来——别人告诉你这么做，你照做，出了岔子再回头找原因。这一篇要做的是把它们收成一个形状，让它们从几条互不相干的纪律，变成同一个数学形状的不同侧面。

## 哲学阐述

范畴论在这里的位置要说清楚：它不替换前面任何一篇的数学，只是给前面那些东西换一套说法。同一套说法里只有三个词——对象、态射、交换图。对象是东西，态射是东西之间的箭头，交换图是「两条路走下来结果一样」。

前面几篇里的东西，在这套说法里各归各位：

集合与逻辑那一篇，对象是集合，态射是集合之间的函数，关系和逻辑式都是在这套东西上说出来的话。

状态机那一篇，对象是状态，态射是操作。操作带着前置条件，前置条件就是这条态射只在哪些状态上有定义。

细化那一篇，对象是状态机，态射是「这份实现是那份规格的落地」。注意这条箭头的方向：从具体指向抽象。

并发那一篇，操作还是态射，多出来的是「交错」这个动作——把两个态射按各种顺序摆开。

组合那一篇，对象是各个模块，多出来的是「拼」这个动作——把几个对象拼成一个新对象，各自只通过投影被读到。

没有哪一篇是临时发明了概念，它们只是在不同的地方用了同一个形状。

## 数学表达

这个形状里有三个地方最值得看清楚。

第一处：细化是偏序范畴。把每个规格和实现当对象，把「refines」当态射，任意两个对象之间至多有一条这样的箭头——一份规格不会被两份实现以两种不同方式落地。态射可复合，复合就是传递性：

```text
C ──refines──> A ──refines──> Spec   推出   C ──refines──> Spec
```

读作：具体层落到抽象层，抽象层又落到更高一层，那么具体层直接落到最高那层。这就是「组合之后不用重证整体细化」真正的理由——它不是经验，是这条复合律。再往上说一层，所有细化偏序合起来还构成一个完备偏序，最底下那个元素是「什么都没实现的空壳」，逐步精化的理论老家就在这里。

第二处：组合是积，不是「把字段堆在一起」。积的定义不靠笛卡尔积长什么样，靠一条泛性质：

```text
存在投影 π₁ : M → M₁ 和 π₂ : M → M₂，
使得对任意对象 X 与任意 f : X → M₁、g : X → M₂，
存在唯一的 ⟨f, g⟩ : X → M，让图交换。
```

这一段的中文意思是：`M` 是拼出来的那个大对象，`π₁`、`π₂` 是从大对象里读某一边的两个投影。只要外部调用方声明了它对 `M₁` 和 `M₂` 各自想干什么（`f` 和 `g`），就恰好有一种方式把它们合成一个对 `M` 的动作，除此之外没有别的做法。「恰好一种」这四个字就是「不越界就自动继承」的来源：越界的做法不在这个「恰好一种」里面，所以它压根不是这个对象上的合法操作。

第三处：交错是幺半结构。把单个操作看成态射，把「两个独立执行体各走一步」看成把态射放在一起：

```text
f : S → S，g : S → S   给出   f ⊗ g : S ⊗ S → S ⊗ S
```

读作：两个各自合法的步骤，可以放在一起同时走。`⊗` 是这种「放在一起」的记号。交错的意思是不固定它们谁先谁后，`f ⊗ id` 和 `id ⊗ g` 都能插进来——`id` 读作「这一步什么也不做」，它就是「别人先走」的占位符。

安全性在这套说法里是对象的一个子对象：所有可交换的图都落在这个子对象里。活性不一样，它不是态射能表达的，需要额外一份结构假设——那份假设就是前一篇里的公平调度。这就是为什么公平调度不能白嫖：它不在系统里，是你额外加进去的条件。

把这三处摞起来，就是整条链的形状：

```text
        对象 = 规约 / 状态机 / 模块
        态射 = 细化 / 操作 / 投影
                 │
       ┌─────────▼──────────┐
       │ 细化偏序范畴        │   对象是状态机，态射是 refines
       │ 复合律 → 组合保细化  │
       └─────────┬──────────┘
                 │ 每个对象的内部
       ┌─────────▼──────────┐
       │ 带交错的模块范畴    │   操作是态射，交错是 ⊗
       │ 安全是子对象        │
       └─────────┬──────────┘
                 │ 每个状态的底层
       ┌─────────▼──────────┐
       │ 集合与逻辑          │   对象是集合，态射是函数
       └────────────────────┘
```

每一层的东西都是下一层的对象，每一层的态射都合法复合——前面几篇手写的那一行行前置条件、那座桥、那些投影，全落在某个小格子里。

## 代码实现

这套形状在代码里不是新东西，它天天出现，只是不叫这些名字。

函子就是 `map`。把 `f : A → B` 抬到容器层面，得到 `F(A) → F(B)`，你写的是同一个 `f`，容器替你负责装东西那部分。

```typescript
const payments: Payment[] = ...;
const amounts: number[] = payments.map((p) => p.amount);   // Array 作为函子
```

```rust
let amount: Option<i64> = payment.amount();
let doubled: Option<i64> = amount.map(|a| a * 2);   // Option 作为函子
```

积就是结构体和它的字段访问。`π₁`、`π₂` 在这里叫 `a.0` 和 `a.1`，或者叫字段名；「恰好一种配对方式」在代码里就是那个结构体字面量。

```rust
struct Charge { account: Account, payment: Payment }
let ch = Charge { account, payment };   // 唯一的配对方式
let a = &ch.account;                    // π₁
```

幺半就是可组合的链：每一步的输出是下一步的输入，串起来的顺序不影响「它们各自是正确的」这件事。

```python
from functools import reduce

steps = [check_limit, freeze, debit, append_log]      # 每一步都是 S → S
final_state = reduce(lambda s, step: step(s), steps, init_state)
```

```typescript
app.use(auth).use(rateLimit).use(auditLog);            // 中间件链，同一种串法
```

细化就是接口与实现，细化那一篇已经写透了。接口声明的是抽象层承诺了什么，实现是具体层的落地，编译器替你验「翻译回抽象状态」的一半。

## 本单元练习

一句话回答，不用写证明：

> 给订单加一个新的状态维度之后，为什么只要这个维度自己证了不变量、跨维度操作又只通过投影改它，整体细化就自动成立？

练习不附答案。写完对着这三条自检：

1. 答案里点出了「恰好一种配对方式」这条性质，而不是说「约定如此」
2. 答案里点出了细化态射可复合，而不是说「已经证过所以不用再证」
3. 能说出这三层分别是什么，以及为什么每一层都可以当下一层的对象
